## Project name

GreenTrace

## Tagline

Checks a company's deforestation-free promise against the evidence, explains why down to the database row, and ships every verdict with a receipt anyone can re-check offline.

## Track

The Agent That Can Explain Why

## Short description (300 characters max)

GreenTrace checks a "deforestation-free" claim for the EU Deforestation Regulation: five agents query Zetaris, an Evaluator tries to break every finding, fixed rules decide, and each verdict ships with the one change that would flip it and a receipt one command re-derives offline.

## Long description

**The problem.** The EU Deforestation Regulation (Regulation (EU) 2023/1115) applies to large and medium operators from 30 December 2026: cocoa placed on the EU market must come from land not deforested after 31 December 2020. Companies already publish promises such as "100% of our cocoa comes from deforestation-free farms since 2021". The compliance analyst of an importer has to cross a sustainability report, a supplier registry with GPS plots, delivery records, satellite alerts and forest maps, and then defend the conclusion.

**What GreenTrace does.** Five agents work on one investigation. The Extractor reads the promise and the reports; Nemotron quotes every item, and code drops any quote that is not word for word in the paragraph it cites. The Planner lists what must hold. The Investigator reads the data only through eleven fixed queries (Q0-Q10) on Zetaris and writes each finding as a fact in the Meterless World Model, tied to the rows it rests on. The Evaluator, the only critic, tries to break every finding with its own queries, from a fixed catalogue of refutations (R1-R6, R8, R9); a refutation nobody planned to test sends the plan back to the Planner, and the trace shows it. Then fixed rules in `app/rules.py` decide: PROVEN, CONTRADICTED or UNVERIFIABLE, per claim part. The Writer words the verdict, the single change that would flip it, draft letters to suppliers that ask and never accuse, a plot file, and an audit package.

**Explain why, then prove it.** Every finding names the records it rests on, and the receipt names the exact query and row behind each one. Every verdict ships with `receipt.json`: the SQL, the rows and their hashes, the exact quotes, the rules' hash and the flip. `python verify.py receipt.json` rebuilds the evidence, applies the rules and replays the flip with no model, no database and no network, then prints VALID, or TAMPERED with the row that changed and the verdict the rules give on the data as found. On the committed example, changing the date of alert A-221 to 2019-03-14 prints `TAMPERED: Q4 row 30 (alert A-221)` and the recomputed verdict, PROVEN.

**Look inside a finished run.** None of these re-runs the investigation, and none decides: the rules still do.
- A court of inquiry: a Plaintiff argues for the promise from the pieces the run already read, the Evaluator answers with its own tests, and the rules judge, over up to three rounds. The code strikes any argument whose citation is not a row of the run or whose quote is not word for word. A test checks on the 21 trap cases that the court never changes the verdict.
- The attack log: every refutation the Evaluator tried, card by card, with its query and result.
- An evidence graph from each sentence of the report to its findings, records, queries and sources.
- Deep Trace: the report sentence by sentence, with the SQL and the rows behind each sentence.
- The World Model before and after a what_if: which facts were invalidated or superseded.
- A Contradiction Radar: what each claim needs, and which missing document could flip the verdict.
- The declared area of a plot against its own outline.
- The supplier letter in English, French, Spanish and Portuguese; a model translation is kept only if every id, date, number and quote comes back character for character.
- Ask GreenTrace (`POST /runs/{run_id}/ask`): one question about the run, answered from that run's own lines only. A model answer that cites a line that does not exist, or states a number found neither in the question nor in the lines it cites, is refused and the rules answer instead. Every answer comes with the run's why-chain, drawn from its output by the rules: the evidence rows, the refutations tried on them, the finding, the rule, the verdict and the flip, with what the answer cites highlighted.

**Real maps, real orbits.** The company is synthetic; the forest maps are real. 716,800 cells of 30 m around Soubre, Côte d'Ivoire hold forest in 2020 (EU JRC GFC2020) and the year of tree cover loss (Hansen/UMD). An analyst can draw a plot: on P-042, 3.42 ha of 2020 forest were lost after 2020 while it delivered, so the claim is CONTRADICTED; on P-041, tree cover was lost but the EU map never counted that land as forest in 2020, so GreenTrace says UNVERIFIABLE and asks for a field check instead of condemning it. A time slider applies the same map rule year by year: P-042 is PROVEN up to 2020 and CONTRADICTED from 2021, when 1.50 ha of its 2020 forest was gone. GreenTrace also gives the next daylight Sentinel-2 passes over a plot, computed from the real TLEs of Sentinel-2A, 2B and 2C (CelesTrak, committed in `data/tle/`), as an `.ics` file or Google Calendar links, with a run's evidence expiries and supplier follow-ups; and what each map source says about one plot. A pass is geometry, not a promise that an image will be taken.

**Open to other agents.** The same five operations (check a claim, check a plot file, what_if, explain, verify a receipt) are an MCP server (stdio, and streamable HTTP at `/mcp`) and an A2A agent (`/a2a`, specification 1.0, still answering 0.3 clients). Every investigation is also one OpenTelemetry trace, one span per trace line. Whichever door a request comes through, the same rules decide.

**The website.** https://greentrace-eudr.higgsfield.app is the public face: the home page scrolls through six real Sentinel-2 scenes of P-042 from 2019 to 2026 while the EU 2020 forest cells and the Hansen loss cells appear; while the engine works, an analysis scene flies from the world to the area it queries, with the run's real trace lines; an analyst can check a plot file or run a live investigation with up to 12 tabs (why, what would change it, Ask GreenTrace, the court, the attack log, Deep Trace, the evidence graph, the memory before and after, the radar, the calendar, the letter, the trace). The Ask GreenTrace chat speaks AG-UI to the site's own agent, which has no model and forwards each question to the engine's `/runs/{run_id}/ask`. CopilotKit was tried and left out: its runtime was too heavy for the Cloudflare Worker the site runs on.

**Measured.** On 21 trap cases (an alert one day after the cut-off, latitude and longitude swapped, a namesake cooperative, a prompt injection in an NGO note, the alert source down...), the rules alone score 18/21 in sample mode, and 21/21 with Nemotron 3.5 (measured on 22 October 2026), with no false accusation. Because we wrote those 21 cases, another model (ChatGPT, temporary chat, no memory) wrote a blind set of 10 from a brief that shows the data and the three verdicts but never the code or the rules; its answer was frozen by hash and committed before the first run. GreenTrace scored 7/10 on the rules alone and 6/10 with Nemotron (NVIDIA direct, with 13 rule fallbacks after failed calls), with no false accusation either way. The misses are published as they came (`data/bench_blind.json`): an alert read as its centre point when its area overlaps the plot, a low-confidence alert we call UNVERIFIABLE where the author said PROVEN, a moved plot, and a model reading that dropped an NGO note naming the supplier by its registry id (fixed after the run; the score above is from before the fix). Against one model with everything: Nemotron 3.5 Super alone, given every table, the claim and the verdict rules word for word, scored 7, 5 and 9 of 21 on three passes on 25 October 2026 (11 and 12 on two earlier ones), saying CONTRADICTED where the answer was not 5 to 10 times per pass; on the clean case it placed three alerts inside plots they are about 1.5 km from (`scripts/baseline_model_alone.py`, `data/bench_model_alone.json`). Planted false evidence: forging each of the 3,020 values of the demo receipt one at a time, `verify.py` flags all 3,020 when the hashes are left as they were, and all 177 forgeries that would move the verdict or the flip when a careful forger rewrites every hash (`scripts/tamper_bench.py`); the bench also found, and we fixed, a crash on a forged polygon. Sample mode runs with no key and no network: `docker build -t greentrace .` then `docker run --rm -p 8000:8000 greentrace`. To re-check these claims yourself in about a minute, offline: `python judge.py` (six checks, PASS or FAIL each, report in `logs/judge/report.md`).

**Honest about the demo.** The website and the engine demo both run in sample mode with no model key: the agents use their rule fallbacks instead of Nemotron (the 18/21 path), and the verdict comes from `app/rules.py` as in every mode. The company ChocoDurable, its suppliers and its deliveries are fictional; plots P-041 and P-042 are real places, read on real maps. GreenTrace is decision support for a human analyst: not a legal opinion, not a public rating, and every verdict needs a human review.

**What practitioners told us.** Two posts about GreenTrace on Reddit reached about 20,000 and 780 views, with about 30 upvotes and 30 comments between them (counted by the author on 25 October 2026); the comments back the approach and give advice, and that advice is in the build. "Unverifiable" names the missing evidence and, since 25 October, what the EUDR asks next: an unverifiable risk is not negligible, so the cocoa may not be placed on the market until it is mitigated, and the record is kept for at least five years (`eudr_next` on every verdict). A single point is accepted up to 4 ha but never supports PROVEN from satellite data. A plot file is checked the way the EU system checks it before any analysis: an open ring is closed and reported, a self-crossing outline is refused, the longitude/latitude order is checked, and a point where a polygon is required leaves the plot UNVERIFIABLE (`app/plotfile.py`).

## Sponsor technology explanation

**Zetaris (data layer).** Zetaris is the agents' only access to data. `scripts/load_zetaris.py` attaches a Postgres datasource and compiles the Unified Semantic Layer `eudr` (`data/usl_eudr.sql`): company, suppliers, plots, deliveries, alerts, report paragraphs, and `reference_cells`, the 716,800 real map cells loaded with COPY. Data quality uses Zetaris's native rules (`REGISTER DQ`, read back through `SHOW DQ INVALID RECORD` as query Q0, rules in `data/dq_rules.json`): the rule `in_cocoa_belt` flags plot P-027 in trap case 16, where latitude and longitude were swapped, and the claim becomes UNVERIFIABLE instead of being checked on the wrong place. The agents may only run the eleven queries Q0-Q10 of `app/queries.py`, over the Zetaris REST API (`app/adapters/zetaris.py`), with every value checked before it reaches SQL; Q10 reads the map cells inside a drawn plot. Every answer keeps its SQL, rows and hash, which is what the receipt replays, and what Deep Trace and the court show. In sample mode, which is what the online demo runs, the same eleven queries run on a local SQLite copy of the data; live mode runs them on Zetaris.

**Meterless (build layer): World Model and H-MEM.** The agents share one memory: the official Meterless World Model reference implementation, copied unmodified (`meterless/reference`, upstream commit `1742dec`, every file hashed in `meterless/UPSTREAM.sha256`), which passes its conformance suite 8/8 and runs as a small server inside the same container as the API (`meterless/server.ts`, `app/memory/world_model.py`). The court reads its cards from it, and the "before and after" view diffs it around a what_if. A second Meterless engine, H-MEM, also the unmodified reference (`meterless/hmem`, conformance 13/13), is used for one thing only: one note per supplier a finding concerns, read first by the next investigation and shown as "Seen before"; it never decides and never enters the receipt.

**Meterless Nightshift: every model call, a signed receipt.** Nemotron calls go through Nightshift 1.2.3 on a Windows laptop with no NVIDIA GPU (NVIDIA's cloud models as its provider). Each answer's compute receipt, signed by meterlessd with Ed25519, is verified at call time (`app/adapters/meterless_receipt.py`), named in the trace line and kept. On the 21 trap cases through Nightshift (Nemotron 3 Ultra 550B): 21/21, 89 model calls, 0 rule fallbacks, 89/89 receipts verify (`data/bench_nightshift.json`; `python -m scripts.verify_nightshift_receipts` re-checks them offline). Found in those receipts afterwards: Nightshift's own memory was on, and it added 1 or 2 records of its own to every one of the 89 prompts (`hmem.injected`; the receipts keep the ids, not the text), so the cases of that run were not isolated from each other at the model level. The verdicts still come from the rules on each case's own rows, and a quote counts only if it is found word for word in that case's documents; the next run turns Nightshift's memory off.

**Meterless Scout Intent: the third engine, implemented from its spec.** Meterless publishes Scout as a spec plus an eval harness, no code; ours is `meterless/scout/index.ts`, and it clears every gate of the unmodified official harness (`meterless/scout-evals`): intent top-1, injection precision and recall and tool precision all 1.00, clarification rate 0.06. That corpus is a 32-example smoke set whose prompts are also the registry's examples, so we also measured it on our own texts: of the 27 report paragraphs of the 21 trap cases it blocks only the injection of case 19, and on a held-out set frozen before the first run it blocks 4 of 5 unseen attacks and 0 of 4 clean look-alikes; the miss is published (`data/bench_scout.json`). In GreenTrace, Scout guards every report paragraph before a model reads it, and turns every Ask question into a signed execution contract that Ask verifies before answering; a blocked question reads no line and calls no model.

**What the rules require, and where it is.** The organisers' message of 25 October 2026: Zetaris and a Meterless Engine in a working feature are required; Cursor and NVIDIA are optional. Zetaris answers every query in live mode; the Meterless World Model (and H-MEM) holds the facts. Live runs are kept as proof in `output_examples/live/`; the one of 25 October 2026 uses every sponsor at once: 16 queries answered by Zetaris, the World Model reference server, 5 Nemotron calls through Nightshift with 5/5 signed receipts verified, verdict CONTRADICTED with the same seal as the offline sample run (`24035b45...`).

**Nightshift and the Meterless Runtime: how it is wired.** The model gateway (`app/adapters/llm.py`) speaks the Meterless Runtime provider contract: OpenAI-compatible, the `meterless-app` header, the bearer token read from Nightshift's own `proxy-token` file (never copied), and lanes pinned to model ids. If Nightshift is not running, the chain falls to NVIDIA directly and the trace records why (a `provider_fallback` line); the public demo runs in sample mode with no key at all.

**Cursor (build, optional since the organisers' guide update of 22 October 2026).** The guide now lets teams use any AI coding tool; GreenTrace was built mainly with Claude Code. No Cursor credit was distributed, so Cursor was used on its free plan, whose agent stopped at its usage limit on the first session. What Cursor did and did not do is logged honestly in `docs/CURSOR_LOG.md`; its working rules are in `.cursor/rules/greentrace.mdc`.

**NVIDIA Nemotron (power layer).** Nemotron runs on two pinned lanes: deep for the Extractor, the Planner, the Investigator and the Evaluator (`nemotron-3-ultra-550b-a55b` through Nightshift, which currently excludes Nemotron 3.5 Super VL after repeated empty answers; `nemotron-3.5-super-vl-120b-a12b` on NVIDIA directly), and fast for the Writer and the court's Plaintiff (`nemotron-3.5-lightning-30b-a3b`). The Extractor reads the reports three times and keeps only what at least two readings agree on, each item quoted word for word and checked by code. The Evaluator asks Nemotron which refutations to try from a finding's structure, and code tests each one with its own query. Satellite Lens shows Nemotron Vision the real Sentinel-2 scene behind a demo plot; it labels a 3 x 3 grid and the code checks every cell against the Hansen loss map (CONFIRMED, REJECTED, MISSED BY AI). On the 21 trap cases, the score is 21/21 with Nemotron against 18/21 for the rules alone, measured twice: on NVIDIA directly (22 October 2026) and through Nightshift with every receipt verified (25 October 2026). The newer model paths (the Plaintiff's arguments, the court's judgment, Ask GreenTrace and the letter translation) each check the model's answer in code and fall back to the rules; they are tested with a fake model client only, and the online demo runs without a key. Nemotron proposes; the code decides.

## What is unique

- A verdict you can re-check offline: `python verify.py receipt.json` re-derives it from the rows with no model, no database and no network, and names the row that was changed. We haven't seen an EUDR tool ship a verdict you can re-check offline.
- The flip: every verdict comes with the single change of one value that would turn it around ("The claim would be PROVEN if alert A-221 were dated 2020-12-31"), found by trying each change through the same rules. An alert's date or confidence, or a plot's area or position, can then be changed as a real what_if that re-runs only what depends on it.
- An adversarial court that cannot move the verdict: the Plaintiff argues for the promise, the Evaluator answers, the rules judge, and every citation is checked by code.
- A real EU map that refuses to condemn: on P-041, tree cover was lost, but the EU 2020 forest map did not count that land as forest, so GreenTrace answers UNVERIFIABLE and asks for a field check.
- Answers tied to lines: Ask GreenTrace answers only from the run's own numbered lines, and a model answer that strays is replaced by the rules.
